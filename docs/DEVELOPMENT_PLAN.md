# 풋살 팀 밸런서 — 개발계획서 (v0.1 초안)

> 상태: **컨펌 대기**. 각 단계는 사용자 컨펌 후 다음 단계로 진행합니다.

## 1. 개요

풋살 경기 전에 참석 인원을 기준으로 균형 잡힌 팀(또는 수준별 팀)을 자동으로 편성합니다. 편성 결과는 날짜별로 확정해 JSON으로 저장하고 다시 불러올 수 있으며, PDF로도 출력합니다.

## 2. 기술 스택 (제안)

| 항목 | 선택 | 비고 |
|---|---|---|
| 언어/프레임워크 | **Flutter (Dart)** | 요구사항 14 |
| 1차 타깃 플랫폼 | **Flutter Web** | 설치 없이 PC와 모바일 브라우저에서 사용할 수 있습니다. 같은 코드로 Android와 Windows 빌드도 가능합니다. |
| 상태관리 | `provider` 또는 `riverpod` | 규모가 작아 가벼운 방식을 씁니다. |
| 로컬 저장 | `shared_preferences` (웹에서는 브라우저 localStorage) | 선수 명단과 능력치를 자동으로 보관합니다. |
| JSON 저장/불러오기 | `file_picker` + 웹 다운로드 | 요구사항 10, 11 |
| PDF | `pdf` + `printing` | **한글 폰트(Noto Sans KR)를 내장**해야 글자가 깨지지 않습니다. |
| 날짜 선택 | Flutter 기본 `showDatePicker` (한국어 로케일) | 요구사항 9 |

### 백엔드/DB 판단 (요구사항 15)
- **v1은 백엔드와 DB를 만들지 않습니다.** 선수 명단은 브라우저 로컬 저장소에 두고, 확정한 편성표는 JSON 파일로 저장하는 것으로 충분합니다.
- **백엔드가 필요해지는 경우(제안):**
  1. 여러 사람이나 여러 기기에서 같은 선수 명단을 공유하고 싶을 때 → Firebase(Firestore) 같은 BaaS를 쓰면 서버를 직접 만들지 않아도 됩니다.
  2. AI 모델(요구사항 8)을 사용할 때 → API 키를 브라우저에 노출하면 안 되므로 작은 서버리스 프록시가 1개 필요합니다(예: Cloudflare Workers, Firebase Functions).

## 3. 데이터 모델

```jsonc
// 선수
{ "id": "uuid", "name": "홍길동",
  "stats": { "stamina": 2, "speed": 3, "skill": 1, "teamwork": 2, "condition": 3 } }  // 각 1~3

// 확정 편성표 (JSON 저장 파일)
{
  "schemaVersion": 1,
  "matchDate": "2026-10-11",
  "mode": "balanced",            // balanced(평준화) | tiered(전문화)
  "confirmedAt": "2026-10-07T21:00:00+09:00",
  "teams": [
    { "name": "A팀", "players": [ /* 선수 객체 (능력치 스냅샷 포함) */ ],
      "totals": { "stamina": 10, "speed": 11, "skill": 9, "teamwork": 10, "condition": 12, "sum": 52 } }
  ],
  "unassigned": []               // 인원이 맞지 않아 남은 선수 (규칙에 따라 생길 수 있음)
}
```
- 편성표에는 **능력치 스냅샷**을 저장합니다. 나중에 선수 능력치를 바꿔도 과거 편성표는 그대로 유지됩니다.
- 파일 이름 규칙: `futsal_teams_2026-10-11.json`

## 4. 팀 편성 로직

### 4-1. 팀 수와 팀 인원 결정 (요구사항 4)
참석 인원을 N, 팀 수를 k라고 하면 `5k ≤ N ≤ 7k`를 만족하는 k를 고릅니다.
- 예: 10명 → 2팀(5/5), 12명 → 2팀(6/6), 14명 → 2팀(7/7), 15명 → 3팀(5/5/5), 20명 → 3팀(7/7/6) 또는 4팀(5×4)
- 인원은 팀끼리 최대 1명 차이가 나도록 나눕니다.
- ⚠️ **편성이 불가능한 인원**: 4명 이하, **8명, 9명**(5~7명 단위로는 나눌 수 없음). 처리 방법은 아래 컨펌 질문 Q1에 있습니다.

### 4-2. 선수 점수
- 기본 점수 = 5개 능력치의 합 (5~15점)
- 항목별 가중치는 v1에서 모두 1로 둡니다. 나중에 설정 화면으로 조정할 수 있게 확장합니다.

### 4-3. 평준화 (balanced)
1. 점수 내림차순으로 정렬한 뒤 **스네이크 드래프트**로 1차 배정합니다 (A→B→C→C→B→A…).
2. **교환 최적화**: 두 팀 사이에서 선수를 맞바꿔 아래 비용이 줄어들면 교환합니다. 더 이상 줄어들지 않을 때까지 반복합니다.
   - 비용 = 팀 총점 편차 × 큰 가중치 + 항목별(활동량/스피드/개인기/협동력/컨디션) 팀 합계 편차의 합
   - 총점만 맞추는 것이 아니라 **각 능력치 항목도 고르게** 분산합니다.
3. 동점이 많을 때는 무작위 요소를 넣어 "다시 구성" 버튼을 누를 때마다 다른 조합이 나오게 합니다.

### 4-4. 전문화 (tiered)
1. 점수 내림차순으로 정렬합니다.
2. 1팀에는 상위 선수부터 정원만큼, 2팀에는 그다음 선수들을 배정하는 식으로 차례대로 채웁니다.
3. 경계에서 점수가 같은 선수들은 항목 균형을 고려하거나 무작위로 배정합니다.

### 4-5. AI 모델 사용 (요구사항 8) — 제안
- 위 알고리즘은 **오프라인에서도 결정적으로 동작**하므로 v1의 기본으로 사용합니다.
- 선택 기능 "AI 검토"(온라인일 때만 활성화): 알고리즘이 만든 편성안을 Claude API에 보내 문제점을 짚게 하고 개선된 교환안을 받습니다. 받은 교환안이 실제로 비용을 줄일 때만 적용합니다.
- 이 기능에는 API 키와 프록시 서버가 필요합니다(2장 참고). **v1에서 제외하고 v2로 미루는 것을 권장합니다.**

## 5. 화면 구성 (초안 — 디자인은 별도 컨펌)

1. **선수 관리**: 선수 목록, 추가/수정/삭제, 능력치 5항목 설정(1~3 선택 버튼), 총점 표시
2. **경기 편성** (메인)
   - 경기 날짜 선택
   - 참석 체크 목록(전체 선택/해제), 참석 인원과 예상 팀 구성(예: "12명 → 2팀 × 6명") 표시
   - 편성 옵션: 평준화 / 전문화
   - [팀 구성] → 팀별 카드(선수, 항목별 합계, 총점) 표시, 선수를 드래그해 수동으로 조정
   - [팀 확정] → 편성 잠금 + JSON 저장
   - [불러오기] → JSON을 열어 날짜와 편성을 복원하고 다시 편집
   - [출력] → 확정한 편성표를 PDF로 출력
3. 하단 탭 또는 사이드 메뉴로 1번과 2번 화면을 오갑니다.
